# Frozen Swift oracle: recents, rides and relay rules

`../../fixtures/swift_recents_and_rides_oracle.tsv` was produced by compiling
the ORIGINAL `DestinationSearch.swift`, `TransitItinerary.swift` and
`TruckerRadio.swift` at commit c206b98, the last before their facade switch,
with this harness, and recording its output.
`../../swift_recents_and_rides_oracle.rs` checks the Rust against it: 12,082
records in 15 kinds.

## What it pins

| record | Swift original | Rust twin |
|---|---|---|
| `ci-parse` | pasted coordinates: the tests' forms, hemisphere letters before, after and alone, `ß` uppercasing to `SS`, combining marks, fullwidth and Arabic digits, hex floats, `nan`, `inf`, out-of-range and 600 random well-formed points | `recents_and_rides::parse_coordinate` |
| `rd-consts`, `rd-score` | the cap; the score over NaN, infinite and future times and `Int.max`/`Int.min` uses | `RECENTS_CAP`, `recent_score` |
| `rd-merged` | the merge over case variants, canonically equivalent names, `ß`/`SS`, dotted `İ`, 20-, 21-, 25- and 40-entry lists (Swift's sort past its insertion-sort size) | `merged_recents` |
| `rd-store`, `rd-match` | sixty real `RecentDestinations` fed plans one by one (padded names, "Current Location" in every case), their entries after every fifth plan, and `matching` with limits 0 to 25 | `recordable_name`, `merged_recents`, `matching_recents` |
| `ds-blend` | the suggestion blend, as indices into the pinned rows and the completions | `blend_suggestions` |
| `tp-ride` | the ride multiplier, fallback speed and duration over near-miss mode names | `travel_modes::ride_multiplier`, `fallback_mph`, `ride_duration` |
| `rc-consts`, `rc-rank`, `rc-recommend` | the brand table, rank and booking site over brand names in every case and script, and 900 office lists with equal, NaN and infinite miles | `RENTAL_BRANDS`, `rental_brand_rank`, `rental_booking_site`, `recommend_rentals` |
| `tr-guide`, `tr-purpose`, `tr-advance`, `tr-state` | the cab-radio guide's purposes and car-band labels, the queue's wrap-around step, and the state code and position of every state's relay names | `radio_purpose`, `radio_is_car_band`, `radio_advance`, `radio_state_code`, `radio_position` |

`RentalCars.recommend` sorted `Dictionary.values`, so offices of one brand
rank whose miles do not order came out in the launch's hash-seed order. The
harness writes each such group sorted by bytes (name, then miles bits) and
writes `X<n>` for a limited list that cuts one; the Rust keeps such offices
in the order their brands first appeared, and the test compares groups.

## What the harness never touches

`RecentDestinations` reads and writes an encrypted file in Application
Support through `SecureBehaviorStore`; the stubs replace it, so no store is
read or written. `TruckerRadio` is never instantiated (its init reads
Application Support and UserDefaults); only its static rules run. The stubs
also stand in for `ThrottledNet` (no network) and `FlowsDiag`, and carry
byte-for-byte copies of the state boxes (`LiveHazardFeeds.swift`), the
bridge text helper (`BrandKnowledge.swift`) and the fuel code
(`TripCosts.swift`) at c206b98, generated by `build_and_run.sh`.

## Reproduce

Bridge-linked: `POIRanking`, `DestinationPrediction`, `HybridWalk` and
`RadioTuning` at this commit already call the bridge.

```sh
OUT=/tmp/recents-oracle bash build_and_run.sh   # builds, runs three times, prints sha1 and counts
```

Three runs, one with `SWIFT_DETERMINISTIC_HASHING=1`, were byte-identical
(sha1 3008d8ee424a4d1e43d9e3ad2… of the body; the full value is in the
fixture's header).
